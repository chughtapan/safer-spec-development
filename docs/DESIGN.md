# Design: safer-spec-development — per-folder SPEC.md as a dogfooded TypeScript codemod

Generated by /office-hours on 2026-05-10 (rewritten 17:30 after over-engineering correction)
Branch: spec
Repo: chughtapan/moltzap (conversation workspace); deliverable lives in NEW repo chughtapan/safer-spec-development
Status: DRAFT
Mode: Builder

## Problem Statement

The user invoked `/safer:research` on issue #578 asking how spec-driven development could work for the safer pipeline: per-folder fine-grained specs, formal drift detection, and `/safer:spec` becoming a hard precondition for `/safer:architect`. The research returned EXCELLENT (codex supervisor, confidence 0.80 overall / 0.86 tier-1).

The follow-up conversation iterated ~20 rounds on format, taxonomy, gating, and rendering. The cumulative effect was sprawl. The user reset the framing three times:

1. **Build the system, dogfood it, don't simulate.** Hand-authoring one SPEC.md is hypothetical; running the system end-to-end on real codebases is the real test.
2. **Dogfood the dev tooling, not MoltZap.** safer-spec-development self-hosts; agent-code-guard validates the format; safer-by-default needs only a small change. MoltZap is the eventual production port, not the build target.
3. **Don't reinvent the existing safer modalities.** `/safer:spec`, `/safer:architect`, `/safer:implement-*`, `/safer:review-senior`, `/safer:verify` already exist. The architect already writes stubs with `throw new Error("not implemented")` bodies and `it.todo()` test fixtures. The new system *adds two codemod modes plus lint rules*; it does not redesign the modality flow.

The problem is not "design the perfect format." It is "ship a focused tool that integrates with the existing safer pipeline, dogfood it on the dev tooling repos, then port MoltZap."

## What Makes This Cool

- **Compiler-bootstrapping pattern.** The codemod processes its own source.
- **Type-system-first discipline.** `@spec.assume` and `@spec.guarantee` carry *only* what types can't express. The `spec-type-system-overlap` lint rejects strings that restate type-system facts.
- **Empirically grounded kind taxonomy.** Property kinds align with OOPSLA 2025's 9 statistically-significant categories, weighted by mutation-detection odds ratios.
- **PBT-native coverage signal.** Classifier-coverage via `fc.statistics` (Hypothesis-tradition partition coverage) is the hard gate, not line coverage.
- **No reinvention.** Existing safer modalities handle spec → architect → implement → review → verify unchanged; safer-spec-development adds only the structured-SPEC.md generation, the coverage gates, and the agent-code-guard rules.

## Constraints

- **Stack.** TypeScript + ts-morph + Effect Schema + fast-check + Vitest. All in the user's stack already.
- **Three repos affected.** `safer-spec-development` (new, public, chughtapan org); `agent-code-guard` (existing, gains spec-* rules); `safer-by-default` (existing, gains one architect-phase addition).
- **AGENTS.md ecosystem compatible.** SPEC.md is per-folder; AGENTS.md remains per-package narrative.
- **Self-hosting required.** The codemod must successfully describe its own source.
- **No new state machine.** The existing safer label flow (`planning → review → ...` via `safer-transition-label`) governs spec issues. `safer-escalate` handles Ratchet up.

## Definitions

- **Anchor.** A per-export entry in a SPEC.md's body, identified by the exported symbol name.
- **Per-folder.** A SPEC.md exists for each directory containing an `index.ts`. Flat packages get one at `src/SPEC.md`.
- **Required kind.** A property kind that must appear on an export's `*.spec.test.ts` coverage unless explicitly `@spec.skip`-ed with a reason.
- **Type-system residue.** Behavioral, lifecycle, side-effect, semantic, or concurrency claims that cannot be expressed in TypeScript types, Effect Schema refinements, or agent-code-guard rules. Only residue is permitted in `@spec.assume` / `@spec.guarantee`.

## Reasoning and Evidence

### Per-folder, not per-package or per-file

Measured MoltZap cadences (last 90 days, `git log`): per-package spec files 3–8 edits, source files ~5.1 edits each summing to ~150 source touches per package. Per-package SPEC.md would be out of sync ~95% of the time. Per-file would inflate authoring 10×. Per-folder (every dir with `index.ts`) splits the difference and matches the AGENTS.md hierarchical convention (60K+ repos, Linux Foundation stewardship).

### The 9 kinds (not 7, not 12)

Synthesized from three sources, with empirical filter:
- **Claessen & Hughes 2000** (QuickCheck, ICFP) — algebraic laws as design signal.
- **Wlaschin 2014** (F# for Fun and Profit) — popular taxonomy of 7 patterns.
- **Ravi & Coblenz, OOPSLA 2025** — formalized 12 categories with mutation-testing regression.

OOPSLA's 3 not-statistically-significant categories dropped (Generated-Expression Bounds Checking p=0.0627, Generated-Expression Non-Equality p=0.3299, Constant Inclusion p=0.8969). Remaining 9, with measured mutation-detection odds ratios:

| Kind | Odds ratio | Tier |
|---|---|---|
| Exception Raising | **112.76** | tier-1 must-have for Schema/RpcDefinition |
| Inclusion | **36.42** | tier-1 when result is a collection |
| Typechecking | **19.44** | tier-1 must-have for Schema |
| Commutative Paths | 14.60 | applicable when function has commutative structure |
| Partial Roundtrip | 13.55 | applicable when function is idempotent |
| Roundtrip | 13.02 | tier-1 for Schema and RpcDefinition |
| Constant Bounds Checking | 12.46 | invariant-style |
| Constant Equality | 10.34 | most common in corpus (41%), least effective |
| Constant Non-Equality | 6.12 | weak |

### Type-system-first, not "specs everywhere"

Same principle as agent-code-guard's *"ships no policy defaults; every list option carries `{value, reason}`."* If `tsc + Effect Schema + agent-code-guard` enforces it, the assume/guarantee field is silent on it. `spec-type-system-overlap` lint rejects strings containing `Brand`, `Schema.`, `Type.Object`, type literals, `"is <primitive>"`, etc., and points the author to the right layer.

### Coverage is diagnostic-only

Inozemtseva & Holmes 2014 (ICSE) found line/branch coverage doesn't predict mutation-detection effectiveness when test suite size is controlled. OOPSLA 2025 explicitly does not use coverage in its regression. V8 branch coverage stays tracked as trend signal in SPEC.md frontmatter; the hard gate is `classifier-coverage` (via `fc.statistics` partition declarations).

### Generator quality > input count

OOPSLA: 55% of mutations caught with input #1, 76% within first 20, 86% within Hypothesis's default 100. `numRuns-budget` is therefore the wrong metric. What predicts bug catching is whether the *generator* explores interesting partitions. `fc.statistics(arbitrary, classifier)` declares partitions; the codemod's validate mode enforces each declared partition ≥5% of runs.

### Three repos, not one

Earlier framing put everything in safer-by-default. Structural problem: safer-by-default is markdown + bash + doctrine; adding a ~2000-LOC TypeScript codemod distorts its identity. The user's structural read: *"safer-by-default is just a bunch of skills."* Each repo gets one verb (generate / validate / orchestrate). Release cadence independence.

### Dogfood-self-first

The user rejected hand-authored simulation: *"we are unable to succeed because it's all hypothetical but the answer is to dogfood instead of cheating around it."* Self-hosting (codemod processes its own source) is the strongest coherence test. If the format can't describe the format's implementation, the format is wrong. Same pattern as compilers bootstrapping themselves.

### Existing safer modalities handle the workflow

`/safer:architect` already writes typed stubs with `throw new Error("not implemented")` bodies and `it.todo()` test placeholders, per the existing skill (Phase 4 line 728; Phase 7 line 767 explicitly references `it.todo()`). `it.todo` is Vitest-skipped by default — no special CI workflow needed for architect PRs. The addition is one line in Phase 7: run `pnpm safer-spec generate` so SPEC.md commits with the stubs.

## Premises

1. Build the full system; validate by dogfooding two real codebases.
2. Self-dogfood first (compiler-bootstrapping).
3. safer-by-default is NOT a per-folder SPEC.md dogfood target (wrong artifact shape).
4. Assume/guarantee carries only type-system residue.
5. Skip a property kind via `@spec.skip "<Kind>" reason: "..."`, never silent omission.
6. Hard gates: kind-coverage, classifier-coverage, precondition-pass-rate. Diagnostic only: branch-coverage, mutation-score (weekly).
7. The closed kind enum is the 9 above.
8. Cross-spec coherence reduces to 4 contradiction classes; class 4 (NL invariant) deferred behind calibration.
9. Internal symbol links in SPEC.md must resolve mechanically; external links best-effort via `external-spec-roots.json`.
10. Existing safer modalities (`/safer:spec`, `/safer:architect`, `/safer:implement-*`, `/safer:review-senior`, `/safer:verify`) handle the workflow unchanged. This design adds only codemod modes and lint rules.

### Directive Syntax (closed set of 5)

All `@spec.*` directives live in JSDoc comments. Every directive requires a `reason:` line indented by 2 spaces; missing reason → `spec-directive-parse-error` lint failure.

```ts
/**
 * @spec.purpose Identity layer descriptors.
 */

/**
 * @spec.skip "Partial Roundtrip"
 *   reason: not idempotent; trailing whitespace is significant
 */

/**
 * @spec.residual-contract none
 *   reason: shape and refinements captured by Effect Schema
 */

/**
 * @spec.assume "channel.connect() must complete before this is called"
 *   reason: lifecycle ordering; cannot be encoded in types
 * @spec.guarantee "validates target format before any RPC call"
 *   reason: side-effect contract beyond the return type
 */
```

Multi-line directive bodies are not supported in Stage 1.

### Required-Kind Applicability Matrix

Determined mechanically from each `index.ts` export's type:

| Export shape | Required kinds (must appear or have `@spec.skip`) |
|---|---|
| `Schema.Schema<T>` (Effect Schema) | Roundtrip · Exception Raising · Typechecking |
| `RpcDefinition<P, R>` | Roundtrip · Exception Raising · (Inclusion if `R` is collection) |
| `function` returning `Either<E, T>` / `Result<T, E>` / `Effect<T, E>` | Exception Raising |
| `function` (pure) | One of: Roundtrip / Partial Roundtrip / Commutative Paths / Constant Equality |
| `type` / `interface` / `enum` (no runtime value) | Typechecking only |
| Branded primitive | None (type system covers it) |

| SPEC.md location | Source | Extraction |
|---|---|---|
| `frontmatter.folder` | filesystem | `path.relative(root, dir)` |

| `frontmatter.generated-at-sha` | `git rev-parse --short=7 HEAD` | string |
| `frontmatter.coverage.kind-coverage` | required-kind matrix evaluated against kind-detector output | computed % |
| `frontmatter.coverage.classifier-coverage` | Vitest reporter sidecar JSON (`*.spec.test.classifier.json`) | min partition share |
| `frontmatter.coverage.precondition-pass-rate` | sidecar JSON | 1 − rejection rate |
| `frontmatter.coverage.branch-coverage-*` | V8 c8 report scoped to `*.spec.test.ts` | % |
| `frontmatter.thresholds.*` | `package.json#safer-spec.thresholds` | numbers |
| body `## Purpose` | `@spec.purpose` JSDoc on `index.ts` | raw tag body |
| body `## Architecture / Layer` | eslint config `agent-code-guard/no-upward-layer-import.layers[]` | layer + reason |
| body `## Architecture / Imports allowed/forbidden` | eslint dependency-policy config + ts-morph import scan | bullets + reasons |
| body `## Architecture / Other rules` | filter agent-code-guard rule registry by file pattern | name + description |
| body `## Public surface / <Export>` | per-export from `getExportedDeclarations()` | inlined fenced ts code |
| body `## Public surface / <Export> / Refinements` | walk Effect Schema combinator chain | bullets |
| body `## Public surface / <Export> / Property kinds covered` | kind-detector output | checked-off list vs required-kind matrix |

| body `## Exceptions` | scan first 20 lines of `.ts` files for `// @agent-code-guard/architecture-exception:` | rule + reason + file |
| body `## Files` | filesystem walk + extension categorization | bullets with roles |

### Link Resolution Rules

Five resolvers; every backticked symbol mention in body prose is fed through them. Unresolved *internal* mentions fail the build; external misses are silent.

1. **Local source** — `symbol.getDeclarations()[0]` → `[Symbol](../../path.ts#Lnn)` with `path:nn@<sha7>` footer.
2. **Local property** — kind-detector record → `[property-id](./file.spec.test.ts#Lnn)`.
3. **Cross-spec** — for imports from a workspace sibling, walk to that package's SPEC.md → `[Symbol](../../sibling/src/folder/SPEC.md#symbol-slug)`.
4. **agent-code-guard rule** — static map → `https://github.com/chughtapan/agent-code-guard/blob/main/docs/rules/{category}/{rule}.md`.
5. **External package** — `external-spec-roots.json` lookup → `[symbol](docsUrl)` or null.

Anchor slug discipline: lowercase, hyphen-separated, GitHub-compatible.

### Codemod Modes (four)

*(Expanded from two after /autoplan Eng + DX consensus.)*

| Mode | Command | Job | Used by |
|---|---|---|---|
| `init` | `pnpm safer-spec init [folder]` | Scaffold first SPEC.md + stub `*.spec.test.ts` + `safer-spec.config.{ts,json}` in a fresh repo. Lenient starter thresholds. Picks a leaf folder with `index.ts` if no folder given. Targets TTHW <10 min. | first-time external adopter |
| `generate` | `pnpm safer-spec generate [--folder X] [--write\|--dry-run] [--watch]` | Scrape source + JSDoc + properties + eslint config → emit SPEC.md per folder AND `.safer-spec/<folder>.json` structured sidecar. Idempotent steady-state regeneration. Canonical form (LF endings, lexicographic sort for filesystem lists, source-order for exports, line-number-stripped diff). | author locally; `/safer:architect` Phase 7 |
| `validate` | `pnpm safer-spec validate [--folder X] [--planned\|--implemented]` | Run `generate` to memory, diff against on-disk (excluding `generated-at-sha`, live `coverage.*`, line numbers), read Vitest reporter sidecar JSON, assert gates (kind-coverage 100%, classifier-coverage ≥5%/partition, precondition-pass-rate ≥50%). `--planned` mode (architect PRs): kind-metadata-only check, classifier/precondition skipped. `--implemented` mode (default): full gate. | CI pre-merge; `/safer:verify` |
| `doctor` | `pnpm safer-spec doctor` | Health check: configs, deps, sidecar dir, fast-check version, ts-morph version, format-version compatibility. Surfaces config drift and version skew before the user hits cryptic gate failures. | author locally; CI self-test |

`safer-spec --help` prints discovery; `safer-spec --version` prints CLI version + `spec-format-version` it produces; `safer-spec explain <error-code>` opens the docs page for a lint rule or gate.

The two-mode framing earlier in this design was wrong on a critical point: architect PRs cannot satisfy `validate` as written because stubs throw and have no real classifier output. Splitting `validate` into `--planned` (architect-PR-tolerant) vs `--implemented` (full gate) restores the gate model. Both run in the same CI workflow; the flag is set by the PR's label or by inspection of the stub state.

### Structured JSON sidecar (for agent consumption)

Every `generate` emits a paired `.safer-spec/<folder>.json` alongside `SPEC.md`. The JSON is the canonical artifact for LLM agent consumption (`/safer:implement-*`, `/safer:review-senior`); the markdown is for humans.

```ts
// Schema (Effect Schema, in @chughtapan/safer-spec-core)
const SpecArtifact = Schema.Struct({
  formatVersion: Schema.String,          // e.g. "1.0.0"
  folder: Schema.String,
  generatedAtSha: Schema.String,
  exports: Schema.Array(Schema.Struct({
    name: Schema.String,
    shape: Schema.Literal("Schema", "RpcDefinition", "function", "type", "Branded", "unknown"),
    requiredKinds: Schema.Array(Kind),
    observedKinds: Schema.Array(Kind),
    residualAssumes: Schema.Array(Schema.Struct({ claim: Schema.String, reason: Schema.String })),
    residualGuarantees: Schema.Array(Schema.Struct({ claim: Schema.String, reason: Schema.String })),
    sourceRef: Schema.Struct({ path: Schema.String, line: Schema.Number, sha: Schema.String })
  })),
  coverage: Schema.Struct({ ... }),
  thresholds: Schema.Struct({ ... }),
})
```

Closes the prompt-injection vector flagged by /autoplan Eng + DX: agents consume sanitized structured JSON (size-capped strings, escape-on-emit), never the raw markdown prose.

### Error message format

Every lint rule and validate gate emits four parts: **problem** (one line, what gate fired and on what symbol), **cause** (one line, why), **fix** (concrete snippet copy-pasteable), **docs link** (URL to `docs/errors.md`). Fixture-driven snapshot tests on every error string in Stage 1.

Example (`spec-kind-coverage` on a Schema missing Exception Raising):

```
spec-kind-coverage: Export `Agent` from index.ts is missing required kinds.

  packages/protocol/src/identity/SPEC.md (regenerated from agents.spec.test.ts)
  Required for Schema.Schema<T>:  Roundtrip, Exception Raising, Typechecking
  Found:                          Roundtrip, Typechecking
  Missing:                        Exception Raising

  Fix one of:
    1. Add a property:
         it.prop("rejects-invalid-name", { kind: "Exception Raising", exports: [Agent] },
                fc.string().filter(s => s.length === 0),
                (name) => expect(() => Schema.decodeSync(Agent)({ id, name })).toThrow())

    2. Document why it doesn't apply:
         /** @spec.skip "Exception Raising"
          *   reason: ... */
         export const Agent = ...

  Docs: https://github.com/chughtapan/safer-spec-development/blob/main/docs/errors.md#spec-kind-coverage
```

### Escape hatches

- **Per-file:** `/** @spec.ignore */` at the top of a `.ts` file — entire file skipped.
- **Per-export:** `/** @spec.ignore-export <Name> reason: "..." */` — skip one export.
- **Per-rule, per-glob:** `safer-spec.config.ts` accepts:
  ```ts
  export default {
    ignore: ["packages/experimental/**", "**/*.deprecated.ts"],
    rules: {
      "spec-type-system-overlap": "warn",   // downgrade per-rule
      "spec-residual-contract-missing": "off"
    }
  }
  ```
- **Per-line:** standard eslint-disable comments apply to spec-* rules.

### Upgrade path

`safer-spec.config.ts` accepts:
- `kindsExtension: Kind[]` — additive; preserves OOPSLA 9 as base, adds repo-specific kinds.
- `kindsOverride: Kind[]` — replaces the default 9 entirely (use sparingly).

`safer-spec migrate` walks SPEC.md + config files for format-version transitions; emits a diff for human review; idempotent. Deprecation policy: format-version bumps signposted in CHANGELOG ≥1 version ahead.

### Integration with existing safer modalities (the one delta)

The existing safer pipeline is unchanged:
- `/safer:spec` writes 7-section narrative in issue body (existing).
- `/safer:architect` reads narrative, writes typed stubs with `throw new Error("not implemented")` bodies and `it.todo()` test placeholders, commits draft PR (existing).
- `/safer:implement-*` fills stubs (existing).
- `/safer:review-senior` verifies (existing).
- `/safer:verify` runs `pnpm safer-spec validate --implemented` (existing-verify-modality + new gate).

**The single change to the architect skill:** in Phase 7, after writing stubs, run `pnpm safer-spec generate` so SPEC.md + JSON sidecar commit in the same draft PR as the stubs. The architect PR's CI uses `pnpm safer-spec validate --planned` (kind-metadata-only check); the implement PR's CI uses `pnpm safer-spec validate --implemented`. The mode flag can be inferred from the presence of `it.todo` vs `it.prop` in the diff.

### Property kind metadata authoring API

Stubs carry kind metadata via Vitest's `meta` field (per /autoplan Eng fix #2). The author-facing API hides the `meta` nesting through a `safer-spec-prop` helper:

```ts
import { itSpec } from "@chughtapan/safer-spec-development";

// Stub (architect PR):
itSpec.todo("agent-roundtrip", {
  kind: "Roundtrip",
  exports: [Agent],   // by-value reference, not magic string
});

// Implemented (implement PR):
itSpec.prop("agent-roundtrip",
  { kind: "Roundtrip", exports: [Agent] },
  agentArb(),
  (a) => Schema.decodeSync(Agent)(Schema.encodeSync(Agent)(a)),
);
```

`Kind` is exported from `@chughtapan/safer-spec-core` as a closed string-literal union (IntelliSense completes). The first positional string is the canonical property id (no duplication). `exports` is an array of *values* (not strings); kind-detector resolves names via ts-morph at collection time, so renames stay refactor-safe.

## agent-code-guard new rules (5)

| Rule | Severity | Job |
|---|---|---|
| `spec-directive-parse-error` | error (always-on) | Malformed `@spec.*` JSDoc — missing reason, unknown directive name, body parse failure. |
| `spec-residual-contract-missing` | warn | Exported symbol from `index.ts` with no `@spec.*` directive at all. Drives incremental adoption. |
| `spec-type-system-overlap` | warn → error (after migration window: 5% FPR over 20 PRs) | `@spec.assume` / `@spec.guarantee` strings restating type-system facts. Rejects mentions of `Brand`, `Schema.`, type literals, `"is <primitive>"`, `"matches schema <...>"`. |
| `spec-kind-coverage` | error | Defense-in-depth against the codemod's `validate` gate: each export from `index.ts` has properties covering the required kinds (or `@spec.skip` with reason). |

`spec-classifier-coverage` was dropped from the ESLint rules per /autoplan Eng fix — classifier-coverage depends on test execution artifacts and IDE lint feedback is stale by construction. Keep classifier-coverage as a hard gate in `pnpm safer-spec validate` only.

The four rules duplicate some of `pnpm safer-spec validate`'s checks deliberately — defense in depth, plus the IDE feedback loop is faster than running the codemod.

## Approaches Considered

### Approach A: Single-repo (everything in safer-by-default)
- *Pros:* one repo, shared CI.
- *Cons:* mixed-language pain; safer-by-default's identity becomes confused.
- *Risk:* medium — works initially, becomes weird.

### Approach B: Four-package factoring (recommended, /autoplan-revised)
- `@chughtapan/safer-spec-core` (new package, can live inside `safer-spec-development` repo): shared kinds enum + directive grammar + JSON sidecar schema + format-version constant.
- `@chughtapan/safer-spec-development` (new repo): codemod + Vitest reporter + CLI (init/generate/validate/doctor/migrate/explain) + `safer-spec-prop` helper.
- `chughtapan/agent-code-guard` (existing): adds 4 spec-* rules (drop `spec-classifier-coverage` from lint per /autoplan Eng fix — telemetry doesn't belong in static lint; keep in `validate` only).
- `chughtapan/safer-by-default` (existing): one-line Phase 7 addition to architect skill.
- *Effort:* **~5-6 weeks human / ~40-50 CC-hours** (revised UP after /autoplan Eng + DX fixes — see Stage 1 LOC table).
- *Pros:* one verb per package; shared `core` prevents drift; release cadence independence per package.
- *Cons:* upfront repo + 2-package setup; cross-package coordination for `core` bumps.
- *Risk:* low.

## Recommended Approach

**Approach B (revised).** Four-package factoring with shared core. Effort revised UP from the prior cut because /autoplan Eng + DX consensus added: `init` + `doctor` modes, structured JSON sidecar, full CLI surface with `--help`/`migrate`/`explain`, error message format, escape hatches, upgrade path, 7 docs files in v0.1.0. None of these were over-engineering; they're the difference between an expert-only compliance tool and a developer experience.

## Success Criteria (Validation Gate)

System is ready to port MoltZap when all hold:

1. **safer-spec-development self-hosts.** `pnpm safer-spec validate` against the codemod's own source passes with no diff and no gate failures.
2. **agent-code-guard CI green for ≥4 weeks** with the new spec-* rules active. False-positive rate <10% on the last 5 PRs.
3. **At least 1 spec round-trip with explicit rejection** through the existing safer state machine (`planning → review` → revision → `review` → architect).
4. **Cold-start readability.** A fresh agent session reads one dogfooded SPEC.md and produces a description listing purpose, public surface, one residual contract — without asking >2 clarifying questions.
